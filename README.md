# 九牧 ZS800I — Home Assistant BLE 集成

本地蓝牙、无需云端或MQTT。0.3.1控制**写出即返回、后台观察回读，新操作可结束旧观察**，不再等匹配后才接受下一条；保留持续连接、启动只读预热和可选连接策略。支持广播名 `JOMOO_SMART_237371` 的 ZS800I；`279029` 是另一套协议，不在此版本支持列表中。

## 控制功能

- **12个动作按钮**：停止、大冲、小冲、开盖（保留圈状态）、关盖关圈、开盖开圈、开盖关圈、臀洗、妇洗、自动臀洗、自动妇洗、暖风。
- **7个开关**：氛围灯、脚感、预湿润、自动发泡、水路UV、关盖冲厕、自动小冲。
- **3个整数档位**：水温0–5、座温0–5、风温0–3。数字是设备档位，不是摄氏度。
- 新增“最后控制结果”，区分发送中、回读匹配、已发送未确认、回读不匹配、通信失败；控件状态只取实际回读，不提前假定成功。

控制来源为同协议的公开控制器和237371型号表，详见[控制协议与验证范围](docs/controls.md)。源码支持不等同于每项已实机验证；冲水、清洗、盖圈等动作仍需逐项实物核对。

19字节控制不是纯动作帧：它携带温度、喷嘴、水压等设置。本实现采用上游普通（非定时、非自定义用户）构造模板、显式映射本连接的有效FA，而非复制状态帧回写；保留已映射字段，不宣称未知位完全无损。

## 安装

建议使用近期稳定版Home Assistant。`hacs.json`声明2025.1为最低版本，但未进行完整版本矩阵测试。

### HACS自定义仓库

仓库：`https://github.com/jadonding/Jomoo_Smart_ZS800I`，类别选择 **Integration**。安装后重启HA。

### 手动安装

从仓库或[0.3.1安装包](dist/jomoo_zs800i-0.3.1.zip)取出 `custom_components/jomoo_zs800i`，复制到HA配置目录下同名位置，重启HA。

### 添加设备

设置 → 设备与服务 → 添加集成 → **九牧 ZS800I**，输入设备蓝牙MAC。也可确认HA自动发现的精确名称设备。

默认**持续保持连接**：添加/启动后后台发送只读查询预热，没有周期轮询或自动动作；连接期间收到设备通知会更新状态。初次尚未收到有效状态的字段为unknown，已有字段保留最后观察快照。设置 → 设备与服务 → 九牧 → 配置，可选择持续保持、空闲60秒断开、每次操作后断开。

厂商小程序需要直连时，按 **释放蓝牙连接**；它只断开连接，不发送马桶动作，也不会立即后台抢连。下一次HA查询/控制才重新连接。低延迟实测与边界见[连接与延迟](docs/latency.md)。

也可用可选YAML导入同一配置项（不会自动查询）：

```yaml
jomoo_zs800i:
  address: "AA:BB:CC:DD:EE:FF"
```

重启后自动创建/复用该地址的集成项；已有配置项不会重复创建。YAML只负责首次导入，删除YAML不自动删除已有集成。

### 中文界面

系统语言选择简体中文后重载集成，首次在英文环境注册的实体名称会按中文资源显示。0.1.2还将查询结果设为枚举，因此显示“查询成功/正在查询/连接失败”等中文，而不是内部状态代码。实体ID保留原值，避免破坏已有引用。

提供[中文面板示例](examples/dashboard-jomoo.yaml)，包含刷新、查询结果、盖圈/着座/氛围灯及温度档位。示例使用早期英文环境生成的实体ID；其他安装请按实际ID调整。将示例放进HA配置目录，并注册一个不影响现有概览的新仪表盘：

```yaml
lovelace:
  dashboards:
    jomoo-toilet:
      mode: yaml
      title: 九牧马桶
      icon: mdi:toilet
      show_in_sidebar: true
      filename: dashboard-jomoo.yaml
```

## 蓝牙部署

- HA OS：使用正常工作的本机/USB蓝牙适配器。
- HA Container：宿主机运行BlueZ，映射 `/run/dbus:/run/dbus:ro`，使用host网络；见 `compose.yaml` 示例。Ubuntu上实测docker-default AppArmor会阻止DBus AddMatch；示例仅对此容器设置 `apparmor:unconfined`，未更改主机全局AppArmor策略。其他系统可按实际情况省略该设置。
- 主机防火墙需允许用户局域网访问8123/TCP；不要为了本项目停用防火墙或开放所有来源。
- ESPHome：也可通过支持主动连接的蓝牙代理提供连接通道；本项目未做代理实物验证。
- 设备应在HA蓝牙覆盖范围内；手机小程序占用连接时先断开手机。

`compose.yaml` 和 `configuration.yaml` 用于全新Container部署示例。已有HA请只安装自定义组件，勿覆盖原配置。

## 实体

| 实体 | 说明 |
| --- | --- |
| 刷新状态 | 复用/建立连接、发送固定查询、读取新通知 |
| 释放蓝牙连接 | 只释放连接，不发送马桶动作；供厂商小程序直连 |
| 最后状态时间/最后查询结果 | 区分新观察、旧快照与失败 |
| 原始FA/E9/EA | 大写HEX，不含空格，最多42字符；长帧显示截断 |
| 型号/设备地址 | 配置信息 |
| 水温/座温/风温档位 | 源码语义推导，不是摄氏度 |
| 着座/盖打开/圈打开 | 源码语义推导，仍需逐项实物操作对照 |
| 氛围灯状态 | 状态位已通过单字段控制回读验证 |

所有动态值是**最后观察快照**，并非断开后的连续实时状态。实体附快照标记、查询结果、观察时间。

## 连接与故障行为

使用HA蓝牙栈提供的可连接BLEDevice，不直接调用BleakScanner，不向Bleak传裸地址触发隐式扫描。
刷新与控制共用锁。优先使用当前扫描器实际保有的连接来源；缺少当前来源时，通过HA共享扫描最多等待20秒新广播，再通过 `bleak_retry_connector.establish_connection` 建连。单次连接超时20秒、最多3次外层尝试（HA包装器可能内部重试，整体可能超过60秒）；FFE1属性有 `write` 时带响应写，否则使用 `write-without-response`。
固定状态查询是 `F3 F4 08 92 00 E2 00 00 00 00 7C FC`。控制额外发送允许列表中的短开关帧或19字节动作/设置帧，无任意raw写入服务。

短开关为独立字段帧，省去无用途的E9预读；19字节控制仍要求本事务的新完整FA和E9，盖圈还要求新EA。只复用传输连接，不用同连接旧帧替代本次控制基准。档位调整须空闲；盖圈须无人、空闲且已停止运动；清洗/烘干须着座。无有效基准时停止下发，不用磁盘旧快照补齐控制字段。每项控制只发送一次，只有状态查询可重复；发送后回读单独收集，回读匹配表示观察到了目标状态，不宣称命令因果或动作全部完成。
手动查询在发送后8秒预算内等待新有效通知，首包后额外收集0.4秒突发通知。默认保留连接，设备推送会更新观察值；不启动周期轮询。动作前采用短暂安静窗口避免固件丢包；动作只写一次，回读查询间隔最多1秒、保留约9秒确认窗口。
收到有效通知只证明本次连接的状态接收有效，不独立证明所有通知都由查询触发。

查询失败保留旧快照和原观察时间，并更新失败结果；本次没有新通知时不使用旧缓存冒充成功。
控制前台只串行预检和写入，最多容纳4个请求、排队最多10秒；后台确认不占用等待锁，新控制会结束旧观察。仍保留固件短发送间隔和动作前检查。卸载会清理观察任务与连接。出现“已发送，未确认”时先核对设备状态，避免重复点击动作。当前没有任意原始写入、强制疏通、颜色/风速或自定义定时模式接口。

## 协议与解析边界

帧头F3F4，`总长度=frame[2]+4`，`sum(frame[2:-2])&255==frame[-2]`，帧尾FC。
数据仅从 `frame[6:-2]` 取；校验和与帧尾绝不当作状态字段。
支持碎片、粘包、噪声、坏校验/坏长度重同步；单次输入上限4096字节，未完成帧缓冲有界。

- FA：水温 `(payload[0]>>4)&7`；座温 `payload[1]&7`；风温 `payload[2]&7`；氛围灯 `payload[5] bit4`。
- E9：着座 `payload[0] bit7`。
- EA：圈打开 `payload[0] bit1`，盖打开 `payload[0] bit3`。237371的型号配置关闭E9/E2盖圈来源，因此仅使用EA。

参考项目的19字节全量设置会重新构造多个字段，未保留未知位；本集成没有照搬该写入接口。

## 开发与打包

```sh
python -m unittest discover -s tests -v
python build.py
```

单元测试使用HA/bleak stub，不连接硬件。覆盖严格校验、分片/粘包/重同步、短载荷、两种写入模式、超时、取消清理、缓存、锁及打包元数据。
`build.py` 输出可手动安装的ZIP和SHA256；包中不含设备地址、账户、HA存储或扫描报告。
